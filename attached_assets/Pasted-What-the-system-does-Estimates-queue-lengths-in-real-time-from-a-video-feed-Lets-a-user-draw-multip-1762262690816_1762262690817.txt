What the system does
Estimates queue lengths in real time from a video feed.
Lets a user draw multiple “queue zones” (polygons) on the first frame of the video.
Detects people with YOLOv8, maps them into the defined zones, and counts per-queue.
Publishes live analytics (counts, best/worst queue, totals) and a rendered frame overlay.
Shows a live dashboard with auto-refresh, charts, and optional voice announcements.
How it works (end-to-end flow)
Define queue zones
You upload/select a video in the app and launch the polygon tool.
The tool displays the first frame and lets you draw polygons (one per queue).
The polygons are saved to data/polygons.json.
Run detection
The backend (detection_engine.py) loads:
The video
The polygons from polygons.json
A YOLOv8 model (Ultralytics)
For each frame:
It runs person detection (class 0).
Filters tiny boxes (noise) using a relative area threshold.
Computes the bottom-center point of each box and checks which polygon it falls in (point-in-polygon via ray-casting).
Smooths counts over a short window (deque) to reduce jitter.
Draws overlays (polygons and counts) on the frame.
Writes outputs to data/queues.json and data/live_frame.jpg.
Live dashboard
The Streamlit dashboard page reads data/queues.json and data/live_frame.jpg repeatedly (auto-refresh).
It shows:
The live frame with overlay
Cards with total people, best queue, and queue-by-queue stats
A bar chart for queue comparison (Plotly)
A data freshness indicator
Optional audio guidance
At a set interval (e.g., every N seconds), it can announce “Please move to Queue X” using Edge TTS + pygame.
Core data contracts (files)
data/polygons.json

Contains the list of queue polygons and metadata.
Example fields: video_path, timestamp, queue_count, polygons (array of arrays of [x,y] points).
data/queues.json

Produced continuously by the detector for the dashboard.
Fields:
timestamp: ISO time when written
total_queues: int
queue_counts: array of ints (one per queue)
total_people: sum of queue_counts
best_queue: index (1-based) of the queue with smallest count
worst_queue: index (1-based) of the queue with largest count
recommendation: short guidance string
data/live_frame.jpg

The latest frame with overlays drawn.
Key algorithms and choices
Detection: Ultralytics YOLOv8 (person class only).
Position proxy: bottom-center of bounding box represents a person’s place in line.
Zone assignment: point-in-polygon (ray-casting).
Noise filtering: drop boxes below a relative area threshold (e.g., <0.3% of frame).
Smoothing: moving average of queue counts over the last few frames (deque).
Performance: optionally process every N-th frame to balance speed vs. accuracy.

Why these choices work well
Separation of concerns:
Backend detector writes to files (simple, robust IPC).
Frontend just reads and renders (keeps Streamlit reactive and stable).
File-based data contracts:
Easy to debug by opening queues.json.
Portable and doesn’t require a database for basic setups.
YOLOv8:
Good accuracy for person detection out-of-the-box.
Configurable thresholds for performance tuning.

Limitations and next steps (talking points)
People assignment is per-frame, not full multi-object tracking. Upgrades:
Add tracking IDs (ByteTrack/OC-SORT) to improve stability and deduplicate detections.
Estimate wait time via flow rate or service rate rather than a simple per-person multiplier.
Communication layer:
Files are simple but can be replaced with a message bus (Redis, WebSocket, Kafka) for distributed setups.
Performance:
Use a smaller YOLO model for speed on edge devices or GPU acceleration for higher FPS.
Deployment:
Containerize (Docker), run on a server, and serve the dashboard over HTTPS.
